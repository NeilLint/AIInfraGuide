自回归解码有一条铁律：生成第 $t+1$ 个 Token 必须先有第 $t$ 个。这条串行依赖让 Decode 阶段每次前向只产出 1 个 Token，而每次前向都要把整个模型权重从显存里搬一遍——算力大量空转。投机解码（Speculative Decoding）的破局思路是"先猜后验"：让一个便宜的草稿机制一口气猜出多个 Token，再让大模型**一次前向并行验证**，配合 Rejection Sampling 保证输出分布与大模型自己逐个生成**严格一致**。这一节把整条链路彻底讲透：为什么验证几乎免费、无偏性怎么一步步证（面试最爱考的推导）、Draft 从独立小模型到 N-gram 再到 Medusa/EAGLE 怎么演进、什么场景下收益会衰减甚至为负，以及在 vLLM 里怎么配、怎么看接受率。

## 1. 为什么投机解码有效：Decode 的算力在空转

### 1.1 验证 k 个 Token ≈ 生成 1 个 Token

第 1 章的结论要先搬过来：**小 Batch 下的 Decode 是 Memory Bound（访存受限）**。每生成 1 个 Token，GPU 都要把全部模型权重（外加 KV Cache）从 HBM 读进片上，而对应的计算量只有约 $2P$ FLOPs（$P$ 为参数量）。用一个 7B 模型算笔账：

- **访存**：FP16 权重约 14 GB。在显存带宽约 2 TB/s 的 A100 上，光搬权重就需要约 7 ms——这是每步 Decode 的硬地板。
- **计算**：$2 \times 7\text{B} = 14$ GFLOPs。A100 的 BF16 峰值算力约 312 TFLOPS，这点计算只要约 0.05 ms。

也就是说，单请求 Decode 时 GPU 的算力利用率**不到 1%**——它 99% 的时间在等数据。现在关键一步来了：如果这次前向不是处理 1 个 Token，而是**并行处理 $k$ 个 Token**（像 Prefill 那样），权重还是只搬一遍（14 GB 不变），计算变成 $k \times 14$ GFLOPs。取 $k=5$，计算耗时约 0.22 ms，仍然远低于 7 ms 的访存地板。

📌 **关键点**：**在 Memory Bound 区间，一次前向验证 $k$ 个 Token 的墙钟时间 ≈ 生成 1 个 Token 的时间。** 验证近乎免费，因为它消耗的是本来就在空转的算力。投机解码的全部收益都建立在这个不对称性上：猜（串行、便宜）+ 验（并行、免费）。

### 1.2 加速比的定量模型

设草稿机制一次猜 $\gamma$ 个 Token，定义两个量（沿用 Leviathan et al. 2023 的记号）：

- **接受率 $\alpha$**：单个草稿 Token 被 Target 接受的期望概率（假设各位置近似独立同分布）；
- **草稿开销 $c$**：草稿生成一个 Token 的耗时与 Target 一次前向耗时之比。

一轮"猜 $\gamma$ 个 + 验一次"能产出的 Token 数是个截断几何分布：连续接受 $i$ 个的概率是 $\alpha^i$，全部接受还能白赚 1 个 bonus Token（见第 2 节），所以每轮期望产出：

$$
\mathbb{E}[\#\text{tokens}] = 1 + \alpha + \alpha^2 + \cdots + \alpha^{\gamma} = \frac{1-\alpha^{\gamma+1}}{1-\alpha}
$$

一轮的墙钟时间是 $\gamma$ 次草稿前向加 1 次 Target 前向，即 $T_{\text{target}} \cdot (\gamma c + 1)$（这里用了 1.1 节的结论：验证 $\gamma$ 个 Token 的 Target 前向 ≈ 一次普通 Decode 前向）。于是**期望加速比**：

$$
S(\alpha, \gamma, c) = \frac{1-\alpha^{\gamma+1}}{(1-\alpha)\,(\gamma c + 1)}
$$

把公式代几组数感受一下量级（取 $\gamma = 4$，纯公式推算，非实测）：

| 接受率 $\alpha$ | 每轮期望产出 | $c=0.05$ 时加速比 | $c=0.2$ 时加速比 |
|---|---|---|---|
| 0.9 | 4.10 | **3.41×** | 2.28× |
| 0.8 | 3.36 | **2.80×** | 1.87× |
| 0.6 | 2.31 | 1.92× | 1.28× |
| 0.4 | 1.65 | 1.37× | 0.92×（**负收益**） |

三条规律直接从公式读出来：

1. **$\alpha$ 是命门**：接受率从 0.8 掉到 0.4，加速比从 2.8 倍掉到 1.4 倍以下；
2. **$c$ 必须小**：草稿开销 $c=0.2$ 时，低接受率场景直接负收益——草稿白算了，Target 还得逐个重来；
3. **$\gamma$ 不是越大越好**：$\alpha$ 高时加长草稿有利（$\alpha=0.8, \gamma=8, c=0.05$ 时约 3.1 倍），$\alpha$ 低时加长草稿只是白烧草稿时间（$\alpha=0.4, \gamma=8$ 时反而降到约 1.2 倍）。最优 $\gamma$ 是 $\alpha$ 与 $c$ 的函数。

⚠️ **注意**：这个模型有个隐含前提——"验证不额外花时间"只在**算力空闲**（小 Batch、Memory Bound）时成立。Batch 大了这个前提会塌掉，这是第 8 节收益边界的核心。

后续所有方案——独立小模型、N-gram、Medusa、EAGLE，以及在预训练阶段就内置草稿头的 MTP 路线（专门见 5.6 节）——本质上都是在这三个变量上做文章：**把 $\alpha$ 推高、把 $c$ 压低、把 $\gamma$ 调对**。

## 2. Speculative Sampling：先猜后验的完整流程

### 2.1 框架与记号

两个角色：

- **Draft（草稿）模型**：分布记作 $q(x \mid \text{ctx})$，便宜但不必精确；
- **Target（目标）模型**：分布记作 $p(x \mid \text{ctx})$，就是我们真正要采样的模型。

一轮投机解码分四步：

1. **Draft 猜**：草稿模型从当前上下文出发，自回归地采样 $\gamma$ 个 Token $x_1, \dots, x_\gamma$，并记录每一步的完整分布 $q_1, \dots, q_\gamma$；
2. **Target 验**：把这 $\gamma$ 个草稿 Token 拼在上下文后面，Target **一次前向**。由于因果注意力的性质（和 Prefill/teacher-forcing 是同一件事），这一次前向同时给出 $\gamma + 1$ 个位置的分布 $p_1, \dots, p_{\gamma+1}$——第 $i$ 个是"看到前 $i-1$ 个草稿 Token 后，下一个 Token 的分布"；
3. **从左到右逐个裁决**：对第 $i$ 个草稿 Token $x_i$，以概率 $\min\!\left(1, \frac{p_i(x_i)}{q_i(x_i)}\right)$ 接受；一旦拒绝，从**残差分布** $\mathrm{norm}\big(\max(0,\, p_i - q_i)\big)$ 中重采样一个 Token 顶上，本轮立即结束；
4. **Bonus Token**：如果 $\gamma$ 个全部接受，还能直接从 $p_{\gamma+1}$ 采样一个额外 Token——反正这个分布已经算出来了，不拿白不拿。

所以每轮产出的 Token 数在 $[1, \gamma+1]$ 之间：最差也有 1 个（拒绝时的重采样 Token），**永远不会比朴素解码产出更少**——会亏的只是草稿时间。

### 2.2 伪代码

```python
def speculative_decode_step(ctx, gamma):
    # ---- 1) Draft：小模型自回归猜 gamma 个 token ----
    draft_tokens, q_dists = [], []
    for _ in range(gamma):
        q = draft_model.forward(ctx)              # q(· | ctx)，完整分布
        x = sample(q)
        draft_tokens.append(x); q_dists.append(q)
        ctx = ctx + [x]

    # ---- 2) Verify：大模型一次前向，拿到 gamma+1 个分布 ----
    p_dists = target_model.forward_parallel(ctx)  # p_1 ... p_{gamma+1}

    # ---- 3) 从左到右做 rejection sampling ----
    outputs = []
    for i, x in enumerate(draft_tokens):
        p, q = p_dists[i], q_dists[i]
        if random.uniform(0, 1) < min(1.0, p[x] / q[x]):
            outputs.append(x)                      # 接受
        else:
            residual = normalize(maximum(p - q, 0))
            outputs.append(sample(residual))       # 拒绝：残差分布重采样
            return outputs                         # 本轮结束（后面的草稿作废）

    # ---- 4) 全部接受：白赚一个 bonus token ----
    outputs.append(sample(p_dists[gamma]))
    return outputs
```

两个容易被忽略的实现细节：

- **拒绝位置之后的草稿全部作废**，它们在 Target KV Cache 里已写入的条目要回滚/丢弃（工程上这正是投机解码与 PagedAttention 块管理的交互点，见第 8.4 节）；
- 接受判据用的是 $p, q$ **对同一个具体 Token 的概率比**，所以 Draft 必须把每一步的完整分布（至少是所采 Token 的概率）留下来。

### 2.3 贪心解码的特例

如果 Target 用贪心解码（temperature = 0），$p$ 退化为 one-hot，接受规则退化为**精确匹配**：草稿 Token 恰好等于 Target 的 argmax 就接受，否则直接用 Target 的 argmax 顶上。很多人第一次接触投机解码时理解的"猜对就收、猜错就换"其实只是这个特例；带随机采样时必须用完整的 Rejection Sampling 规则，否则分布就偏了——为什么不偏，下一节证明。

## 3. 无偏性证明：接受的 Token 为什么严格服从 Target 分布

这是整个投机解码的理论基石，也是面试中最常被要求"手推一遍"的内容。要证的命题：

> **命题**：按第 2 节的接受-拒绝-重采样规则产出的单个 Token $X$，满足 $\Pr(X = x) = p(x)$，对词表中任意 $x$ 成立。即输出分布与直接从 Target 采样完全一致。

### 3.1 规则回顾

固定某个验证位置（省略下标），规则是：

1. 从草稿分布采 $\tilde{x} \sim q$；
2. 以概率 $\min\!\left(1, \frac{p(\tilde{x})}{q(\tilde{x})}\right)$ 接受，输出 $X = \tilde{x}$；
3. 若拒绝，从残差分布 $p'(x) = \dfrac{\max\big(0,\, p(x) - q(x)\big)}{\sum_{y} \max\big(0,\, p(y) - q(y)\big)}$ 重采样，输出 $X \sim p'$。

### 3.2 第一步：接受并输出 x 的概率

"输出 $x$ 且是通过接受路径"要求草稿恰好采出 $x$、且接受判定通过：

$$
\Pr(\text{accept},\, X = x) = q(x) \cdot \min\!\left(1, \frac{p(x)}{q(x)}\right) = \min\big(q(x),\, p(x)\big)
$$

最后一步分两种情况验证：若 $p(x) \ge q(x)$，$\min$ 内取 1，乘积为 $q(x)$；若 $p(x) < q(x)$，乘积为 $q(x)\cdot\frac{p(x)}{q(x)} = p(x)$。两种情况合起来正是 $\min(p(x), q(x))$。

### 3.3 第二步：总拒绝概率

对所有可能的草稿 Token 求和：

$$
\Pr(\text{reject}) = 1 - \sum_{y} \min\big(p(y), q(y)\big)
$$

利用恒等式 $\min(a, b) = a - \max(0,\, a - b)$，令 $a = p(y)$：

$$
\sum_{y} \min\big(p(y), q(y)\big) = \sum_{y} \Big[ p(y) - \max\big(0,\, p(y) - q(y)\big) \Big] = 1 - \sum_{y} \max\big(0,\, p(y) - q(y)\big)
$$

于是：

$$
\Pr(\text{reject}) = \sum_{y} \max\big(0,\, p(y) - q(y)\big)
$$

**这恰好等于残差分布的归一化常数**——这不是巧合，正是残差分布这样构造的原因。顺带指出，这个量还等于两个分布的总变差距离（Total Variation Distance）：

$$
\Pr(\text{reject}) = \frac{1}{2} \sum_{y} \big| p(y) - q(y) \big| = D_{TV}(p, q)
$$

（因为 $\sum_y \max(0, p-q) = \sum_y \max(0, q-p)$，两者相加即 $\sum_y |p - q|$。）

### 3.4 第三步：合并两条路径

拒绝路径输出 $x$ 的概率是"拒绝概率 × 残差分布给 $x$ 的概率"，归一化常数恰好消掉：

$$
\Pr(\text{reject},\, X = x) = \Pr(\text{reject}) \cdot \frac{\max\big(0,\, p(x) - q(x)\big)}{\Pr(\text{reject})} = \max\big(0,\, p(x) - q(x)\big)
$$

两条路径相加：

$$
\Pr(X = x) = \min\big(p(x), q(x)\big) + \max\big(0,\, p(x) - q(x)\big)
$$

再分两种情况：

- 若 $p(x) \ge q(x)$：$= q(x) + \big(p(x) - q(x)\big) = p(x)$；
- 若 $p(x) < q(x)$：$= p(x) + 0 = p(x)$。

两种情况下都等于 $p(x)$。$\blacksquare$

对多步的情形，只需逐位置归纳：位置 $i$ 的验证以"前 $i-1$ 个 Token 已按 $p$ 的正确分布产出"为条件，单步结论逐位传递，整条输出序列的联合分布与 Target 自回归采样完全一致。

### 3.5 三个直接推论（面试加分点）

1. **单 Token 接受率 $\beta = 1 - D_{TV}(p, q)$**。草稿分布与目标分布越接近，接受率越高——这给"怎么提高 $\alpha$"指了唯一的方向：**让 $q$ 逼近 $p$**（蒸馏、对齐、自投机都是在做这件事），而不是让草稿"更自信"。
2. **无偏性对任意 $q$ 成立**，包括 one-hot 的确定性草稿（N-gram 直接复制的 Token 就是 $q$ 为 one-hot 的特例）。这就是无模型方案不需要任何额外证明也无损的原因。
3. **与温度 / Top-k / Top-p 兼容**：只要把这些后处理**先同样作用在 $p$（与 $q$）上**，再执行上面的接受-重采样，产出就严格服从后处理之后的 $p$。vLLM 的 Rejection Sampler 正是对后处理后的分布做验证。温度越低分布越尖，$p$ 与 $q$ 的重叠通常越大，接受率越高——贪心解码往往是接受率的上限场景。

🔑 **核心概念**：**投机解码是无损加速。** 它改变的只有"这些 Token 是怎么被算出来的"，不改变"输出服从什么分布"。任何声称"投机解码会牺牲一点质量"的说法，要么指的是放宽了验证规则的变体（如 Medusa 的 typical acceptance，见第 6 节），要么就是错的。

## 4. Draft 模型怎么选：独立小模型的三道坎

最直接的草稿来源是一个独立的小模型（比如用 0.5B 给 32B 打草稿）。看似简单，工程上有三道坎。

### 4.1 第一道坎：词表与 Tokenizer 必须对齐

Rejection Sampling 逐 Token 比较 $p(x)/q(x)$，前提是**两个模型在同一个词表上说话**。Tokenizer 不同的两个模型，同一段文本切出来的 Token 序列都不一样，概率比根本无从谈起。所以独立 Draft 模型几乎总是选**同家族**模型（如 Qwen 系配 Qwen 系、Llama 系配 Llama 系），vLLM 也要求 Draft 与 Target 词表一致。跨词表投机需要额外的对齐/映射层，属于研究性方案，生产上少见。

### 4.2 第二道坎：分布对齐比模型能力更重要

第 3.5 节的推论指明：接受率取决于 $D_{TV}(p, q)$，不取决于草稿模型本身多强。由此推出两条实践准则：

- **对齐训练历史**：Target 是 Instruct 模型，Draft 也要用同系列的 Instruct 版本。Base 小模型哪怕能力不差，在对话分布上与 Instruct 大模型的风格差异会直接压低接受率。
- **微调/蒸馏有效**：把 Draft 在 Target 的输出上做蒸馏（最小化 $q$ 与 $p$ 的散度），是公认能显著提升接受率的手段（DistillSpec 等工作的核心结论）。面试被问"草稿模型是否需要微调"，标准答案是：不微调也能跑（无偏性不依赖 $q$ 的质量），但在目标任务分布上对齐/蒸馏后接受率更高、加速比更好。

### 4.3 第三道坎：大小与部署形态

- **大小折衷**：Draft 要把 $c$ 压到很小（经验上 Target 的 1/10 ~ 1/50 参数量级），$c$ 大了会吃掉第 1.2 节公式里的全部收益；但太小接受率又上不去。$\alpha$ 与 $c$ 的乘积效应要用实际流量测。
- **部署复杂度**：多养一个模型意味着额外的权重显存、额外的 KV Cache、独立的并行策略（小模型往往不值得切 TP，vLLM 提供 `draft_tensor_parallel_size` 单独指定）。长上下文场景下 Draft 也要维护整条上下文的 KV，开销进一步放大。

💡 **提示**：这三道坎解释了后续所有演进的动机——N-gram 方案干脆把 Draft 模型砍掉（第 5 节）；Medusa/EAGLE 让 Target 自己长出草稿头，天然同词表、同分布、共享主干（第 6、7 节）；MTP 更进一步在预训练阶段就把草稿能力内置进模型（见 5.6 节，此处不展开）。

## 5. 无模型方案：N-gram、Prompt Lookup 与 Suffix Decoding

### 5.1 N-gram / Prompt Lookup：从上下文里"抄"草稿

Prompt Lookup Decoding 的观察极其朴素：**很多任务的输出大量复述输入**。RAG 问答在引用检索片段，摘要在复述原文，代码编辑的新文件与旧文件 90% 相同，多轮对话在重复前文的实体名。既然要生成的内容很可能已经在上下文里出现过，那就不用模型猜，直接**查找复制**：

1. 取当前已生成序列的最后 $n$ 个 Token（$n$ 从 `prompt_lookup_max` 往 `prompt_lookup_min` 递减尝试）；
2. 在 Prompt + 已生成历史里搜索这个 n-gram 最近一次出现的位置；
3. 命中则把它后面的 $K$ 个 Token 原样复制出来作为草稿，交给 Target 验证。

这个方案的 $c \approx 0$（字符串匹配的开销对比一次大模型前向可以忽略），而无偏性由第 3.5 节推论 2 保证——复制出的草稿等价于 one-hot 的 $q$，验证规则照常适用，输出仍严格服从 Target 分布。命中时经常整段整段地接受，输入输出重叠型任务上非常划算；而在开放闲聊这类"输出基本是新内容"的任务上，n-gram 很少命中，草稿几乎全被拒绝——但因为 $c \approx 0$，亏的也只是每步一次字符串查找，几乎无害。

📌 **关键点**：N-gram 投机是**零成本试错**：赢了赢很多，输了几乎不输。所以它是 vLLM 里最值得"无脑先开"的投机方案，尤其是 RAG、摘要、代码编辑、结构化改写场景。

### 5.2 Suffix Decoding：把"抄"做成索引

N-gram 匹配只找"最近一次出现"，而 Suffix Decoding（Snowflake 提出）把历史组织成**后缀树**：对当前请求的上下文和过往请求的输出建索引，草稿沿着树上**经验频次最高**的路径展开，且草稿长度可以按匹配的置信度自适应伸缩。它针对的是比"输入输出重叠"更强的模式——**跨请求的重复**：Agent 工作流里反复出现的工具调用格式、self-consistency 多次采样中的公共片段、批量数据处理中高度模板化的输出。开源实现方面，Snowflake 的 Arctic Inference 以 vLLM 插件形式提供了该算法。

### 5.3 适用场景速查

| 方案 | 草稿开销 $c$ | 擅长场景 | 失效场景 |
|---|---|---|---|
| 独立小模型 | 中（0.05~0.2） | 通用，任务不挑 | 部署复杂、词表受限 |
| N-gram / Prompt Lookup | ≈ 0 | RAG、摘要、代码编辑、改写 | 开放生成（不命中，退化为普通解码） |
| Suffix Decoding | ≈ 0（建树摊销） | Agent 循环、模板化输出、多采样 | 无重复模式的一次性生成 |

## 6. Medusa：多解码头与树注意力

### 6.1 多解码头：让 Target 自己猜未来

Medusa 把"外挂 Draft 模型"变成"给 Target 加几个头"：在主干最后一层隐状态 $h_t$ 上并联 $D$ 个轻量解码头（每个头是一个带残差的单层 FFN 接 LM Head），第 $k$ 个头直接从 $h_t$ 预测位置 $t+1+k$ 的 Token。一次主干前向，同时拿到"下一个词"和"下下个词、下下下个词"的猜测。

训练分两种：**Medusa-1** 冻结主干只训头（不动原模型，安全、便宜）；**Medusa-2** 主干与头联合微调（接受率更高，但要小心保住主干质量）。

结构性弱点也很清楚：$D$ 个头**并行且相互独立**——第 2 个头猜 $t+3$ 时看不到第 1 个头对 $t+2$ 猜了什么，位置越远越接近盲猜，接受率随深度快速衰减。（DeepSeek 的 MTP 用顺序模块保住了因果链，正是针对这一点的改进，对比详见 5.6 节。）

### 6.2 从候选组合到草稿树

既然单个头给不出高置信的唯一答案，Medusa 就让每个头给出 top-$s_k$ 个候选，把多头候选组合成**一棵草稿树**，一次验证多条候选路径。例如头 1 取 top-2 $\{A, B\}$、头 2 取 top-2 $\{C, D\}$：

```text
当前已确认 token（根）
├── A            ← 头1候选1（预测 t+2）
│   ├── A-C      ← 头2候选1（预测 t+3）
│   └── A-D      ← 头2候选2
└── B            ← 头1候选2
    ├── B-C
    └── B-D
```

这棵树覆盖了 4 条长度为 2 的候选延续（A-C、A-D、B-C、B-D），但只有 6 个节点——共享前缀只算一次。实际使用中并不做满笛卡尔积，而是**离线校准一棵稀疏树**：按各头各候选的历史接受统计，把节点预算（如 64 个）分给最有希望的组合——第 1 个头的 top-1 子树分到最多节点，靠后的头只保留少量高置信分支。

### 6.3 树注意力：一次前向验证整棵树

把树验证塞进一次前向的关键是 **Tree Attention**：将树上所有节点按拓扑序拍平成一个"伪序列"追加在上下文后，再构造一个特殊的注意力 Mask——**每个节点只允许看到它在树上的祖先链（以及正常上下文），看不到兄弟分支**。对上面的 6 节点树（拍平为 A, B, C, D, C', D'，其中 C/D 挂在 A 下、C'/D' 挂在 B 下）：

| Query \ Key | A | B | C | D | C' | D' |
|---|---|---|---|---|---|---|
| A（t+2 候选） | ✓ | · | · | · | · | · |
| B（t+2 候选） | · | ✓ | · | · | · | · |
| C（A 的子节点） | ✓ | · | ✓ | · | · | · |
| D（A 的子节点） | ✓ | · | · | ✓ | · | · |
| C'（B 的子节点） | · | ✓ | · | · | ✓ | · |
| D'（B 的子节点） | · | ✓ | · | · | · | ✓ |

（✓ = 允许注意，均含对上下文的注意；对角线为节点对自身。）这样每个节点的隐状态就等价于"沿它的祖先路径顺序解码"算出来的结果——**一次前向，等价于并行跑了所有根到叶的路径**，路径间互不污染。位置编码按节点在树中的深度赋值（兄弟节点共享同一深度的 position id）。验证时从根往下走：每层在被接受节点的孩子里裁决，最终取最长被接受路径。这套树拓扑 + Mask 构造是后续 EAGLE 系列直接继承的基础设施。

⚠️ **注意**：Medusa 论文默认的验证规则是 **typical acceptance**（按阈值放宽的接受判据），它**不是**严格的 Rejection Sampling，输出分布与 Target 不严格一致——这是 Medusa 换取更高接受长度的取舍。要严格无损，需退回贪心精确匹配或标准 Rejection Sampling 验证。面试答"投机解码都是无损的"之前，记得把这个例外说清楚。

## 7. EAGLE：特征级自回归与动态草稿树的三代演进

### 7.1 EAGLE-1：在特征层面做自回归

EAGLE 对 Medusa 的两个诊断：

1. **Token 层自回归太难**：词表是离散的、多峰的，小模型直接猜 Token 效率低。而主干**最后一层的特征（隐状态）是连续的、规律性强得多的序列**，在特征层面做自回归回归（regression）要容易得多。
2. **采样随机性必须喂进去**：只看特征 $f_t$ 无法知道"这一步实际采了哪个词"（温度采样下同一分布可能采出不同词），不确定性会级联放大。解法是把**实际采出的 Token** 的 embedding 一并作为输入。

于是 EAGLE 的草稿模块是一个极轻的结构（约等于 Target 的一层 Decoder Layer）：

$$
\hat{f}_{t+1} = \mathrm{DecoderLayer}\Big( W \big[ f_t \,;\; \mathrm{Emb}(x_{t+1}) \big] \Big), \qquad q(x_{t+2}) = \mathrm{LMHead}\big(\hat{f}_{t+1}\big)
$$

它拿着（上一步特征，上一步实际 Token）预测下一步特征，再复用 Target **冻结的 LM Head** 把特征翻译成分布。草稿在特征层自回归地滚多步，配合 Medusa 式的树验证。因为草稿模块只有一层的开销（$c$ 极小），而特征回归 + 真实 Token 注入保住了因果链，EAGLE-1 的接受长度显著超过 Medusa，成为开源投机方案的事实标杆。

### 7.2 EAGLE-2：草稿树应该因上下文而异

EAGLE-1 沿用离线校准的**静态树**：不管当前上下文是"接下来几乎必然是 `\n    return`"的代码，还是"下一个词有几十种合理可能"的闲聊，树的形状都一样。EAGLE-2 的核心观察：**草稿模型的置信度（各步概率乘积）是接受概率的良好近似**，可以拿来在线地塑造树：

- **扩展阶段（Expand）**：从根开始逐层生长，每层只挑**累积置信度**（根到该节点各步草稿概率之积）最高的 top-$k$ 个节点继续展开——高置信的分支长得深，低置信的分支早早停止；
- **重排阶段（Rerank）**：生长结束后，在全树节点里按累积置信度选出总预算内的 top-$m$ 个节点构成最终草稿树，其余剪掉，再构造树 Mask 送验。

效果是同样的节点预算被花在刀刃上：确定性强的上下文里树长成一条深链（一轮接受十几个 Token 成为可能），发散的上下文里树宽而浅、及时止损。EAGLE-2 因此在相同开销下把平均接受长度再推高一截。

### 7.3 EAGLE-3：放弃特征约束，换来数据可扩展

EAGLE-1/2 训练时要求草稿模块的输出特征 $\hat{f}$ 逼近 Target 的真实特征 $f$（特征回归损失）。EAGLE-3 发现这个约束反而成了瓶颈：它把草稿模块的容量花在"复现 Target 特征"上，导致**加大训练数据量也换不来接受率提升**（不具备 scaling 特性）。EAGLE-3 做了两处手术：

1. **多层特征融合**：不再只用最顶层特征——顶层特征已经高度"面向输出"，丢失了中低层的丰富信息。EAGLE-3 从 Target 抽取**低、中、高多层隐状态拼接投影**后作为草稿输入，信息更全。
2. **Training-time Test（训练时模拟测试）**：直接砍掉特征回归损失，只训 Token 预测；为了解决"训练时喂真特征、推理时只能喂自己上一步的近似特征"的暴露偏差，训练中**显式模拟多步草稿过程**——让模块在自己生成的（不完美的）特征上继续往下滚并计算损失，训练分布与推理分布对齐，误差不再级联放大。

去掉特征约束后，草稿模块的接受率随训练数据量增加而持续上升，EAGLE-3 由此把接受长度推到该系列的新高度。这条"特征级草稿"路线之后与预训练内置的 MTP、半自回归的 DSpark 合流演化，见 5.6 节的完整梳理。

### 7.4 Self-Draft 方案对比

| 维度 | Medusa | EAGLE-1 | EAGLE-2 | EAGLE-3 |
|---|---|---|---|---|
| 草稿形式 | 多头并行预测 | 特征级自回归 | 特征级自回归 | 多层融合特征 + Token 预测 |
| Token 间依赖 | 无（各头独立） | 完整（真实 Token 注入） | 完整 | 完整 |
| 草稿树 | 静态稀疏树 | 静态树 | **动态树（置信度扩展 + 剪枝）** | 动态树 |
| 训练要点 | 训头（可冻结主干） | 特征回归 + Token 损失 | 同 EAGLE-1 | 去特征约束 + training-time test |
| 严格无损 | 默认 typical acceptance（非严格） | 是（标准验证） | 是 | 是 |

## 8. 收益边界：投机解码什么时候会更慢

投机解码不是免费午餐，第 1.2 节公式里的每个变量都可能翻脸。

### 8.1 接受率由任务分布决定

$\alpha = 1 - \mathbb{E}[D_{TV}(p, q)]$ 的直接推论：**输出越可预测的任务，接受率越高**。

- **高接受率**：代码生成（语法结构强约束、缩进/关键字/样板高度确定）、摘要与改写（复述输入）、结构化输出（JSON/表格）、数学推导的格式化部分；
- **低接受率**：开放闲聊、创意写作、头脑风暴——下一个词本来就有很多合理选择，$p$ 是平坦的多峰分布，任何草稿机制都难以对齐；
- **采样温度**：温度越高 $p$ 越平坦，与 $q$ 的重叠越小，接受率越低。同一套配置，temperature=0 与 temperature=1 测出来的加速比可能差出一截。

所以评估投机方案**必须用自己的真实流量**：拿代码 Benchmark 测出来的漂亮加速比，放到闲聊流量上可能所剩无几。

### 8.2 批大小：算力从空闲到紧张，收益从正到负

第 1 节"验证免费"的前提是算力空转。Batch 变大后前提逐渐瓦解：

- Batch 为 $B$ 时，一步 Decode 的计算量正比于 $B$，而权重访存不变——算术强度随 $B$ 线性上升，GPU 逐渐从 Memory Bound 逼近 Compute Bound；
- 开投机后每步实际前向的 Token 数是 $B \times (\gamma + 1)$，等于把"逼近算力瓶颈"的时刻提前了 $\gamma + 1$ 倍；
- 一旦触到算力瓶颈，验证时间不再≈单 Token 前向，而是随 $\gamma$ 线性增长，第 1.2 节的分母从 $\gamma c + 1$ 恶化，加速比坍缩；
- 更糟的是**机会成本**：大 Batch 下每个被拒绝的草稿 Token 消耗的算力，本可以拿去服务别的请求。此时投机解码不但不加速，还在**降低系统总吞吐**——收益为负。

📌 **关键点**：**投机解码本质是"拿富余算力换单请求延迟"的交易**，它是延迟优化，不是吞吐优化。低并发/延迟敏感场景（在线助手、代码补全）收益最大；高并发榨吞吐的离线批处理场景，通常应该关掉，或按负载动态启停（vLLM V0 曾提供按 Batch 大小自动禁用的开关；把"验证多长"做成随负载在线定价的调度问题，正是 5.6 节 DSpark 的主题）。

### 8.3 与量化、长上下文、MoE 的交互

- **量化**：Weight-only 量化（如 W4A16）把每步权重访存降为 1/4，Decode 地板变低、算术强度变高——原本空闲的算力余量变小，投机的"免费验证"空间被压缩，两种优化的收益**不可简单相乘**。另一面，无偏性证明对量化后的 Target 依然成立——投机保证的是"与量化模型自己解码同分布"，它不放大也不修复量化本身的精度损失；但若 Draft 与 Target 一个量化一个不量化，分布差异会体现在接受率下降上。
- **长上下文**：上下文越长，每步访存中 KV Cache 的占比越高，而一次验证 $\gamma$ 个 Token 时 KV 同样只需读一遍——投机的相对收益仍在。此时更优选是无模型方案或 EAGLE 系：独立小模型还得为整条长上下文维护自己的 KV，开销随长度膨胀。
- **MoE**：Dense 模型验证 $\gamma$ 个 Token 不增加权重访存；MoE 下多个 Token 会路由到更多不同专家，专家权重访存随之上升，"验证近乎免费"打了折扣，最优 $\gamma$ 通常要取得更保守。

### 8.4 调度与显存的隐性成本

与 Continuous Batching 结合时，投机解码给调度器出了两道难题：每个请求每步产出 1 ~ $\gamma+1$ 个 Token 不等，KV 块的分配要按最大可能预留、拒绝后要回滚草稿 Token 已写入的 KV 槽位；Draft 模型/草稿头本身也占显存，挤压 KV 块池、间接压低最大并发。这些工程成本在评估"要不要开投机"时都应计入。

## 9. vLLM 实战：三种配置与接受率观测

vLLM 通过 `--speculative-config`（JSON 字符串）统一配置各类投机方案（本节以 vLLM V1 引擎、2025 年后版本的接口为准，字段随版本演进，以 `vllm serve --help` 与官方文档为准）。

### 9.1 方案一：N-gram（零成本，先开再说）

```bash
vllm serve meta-llama/Llama-3.1-8B-Instruct \
  --speculative-config '{
    "method": "ngram",
    "num_speculative_tokens": 5,
    "prompt_lookup_max": 4,
    "prompt_lookup_min": 2
  }'
```

- `num_speculative_tokens`：每轮草稿长度 $\gamma$，即命中后一次复制多少 Token 送验；
- `prompt_lookup_max` / `prompt_lookup_min`：匹配用 n-gram 的最大/最小长度，从大到小回退尝试。

RAG / 摘要 / 代码编辑流量直接可试；开放闲聊流量命中率低，但基本无害（见第 5.1 节）。

### 9.2 方案二：EAGLE 草稿头（通用场景的主力）

```bash
# EAGLE-1 草稿头（社区为主流开源模型训练好的现成权重）
vllm serve meta-llama/Meta-Llama-3-8B-Instruct \
  --speculative-config '{
    "method": "eagle",
    "model": "yuhuili/EAGLE-LLaMA3-Instruct-8B",
    "num_speculative_tokens": 3
  }'

# EAGLE-3
vllm serve meta-llama/Llama-3.1-8B-Instruct \
  --speculative-config '{
    "method": "eagle3",
    "model": "yuhuili/EAGLE3-LLaMA3.1-Instruct-8B",
    "num_speculative_tokens": 3
  }'
```

`model` 指向与 Target 配套训练的草稿头权重——EAGLE 头是对着特定 Target 训的，不能跨模型混用。DeepSeek 系模型则可用自带的 MTP 头（`"method": "deepseek_mtp"`，详见 5.6 节）。

### 9.3 方案三：独立 Draft 模型

```bash
vllm serve Qwen/Qwen3-32B \
  --speculative-config '{
    "model": "Qwen/Qwen3-0.6B",
    "num_speculative_tokens": 4
  }'
```

给出普通 LM 作为 `model` 时即按独立 Draft 模型方式运行。注意事项对应第 4 节的三道坎：同家族同词表、优先选对齐过的 Instruct 版本、必要时用 `draft_tensor_parallel_size` 让小模型不切 TP。V1 引擎对独立 Draft 模型的支持晚于 ngram/EAGLE 落地，老版本可能报错或回退，以所用版本的文档为准。

### 9.4 观测接受率：判断"开得值不值"

vLLM 运行时会周期性输出投机指标日志，形如（数值为格式示意）：

```text
SpecDecoding metrics: Draft acceptance rate: 71.4%,
Mean acceptance length: 3.10, Accepted: 1543 tokens, Drafted: 2161 tokens,
Per-position acceptance rate: 0.82, 0.71, 0.58
```

三个量的读法，直接对应第 1.2 节的公式：

- **Draft acceptance rate** = 被接受草稿数 / 提议草稿数，对应 $\alpha$ 的估计；
- **Mean acceptance length** = 每轮平均产出 Token 数（含 bonus），对应 $\frac{1-\alpha^{\gamma+1}}{1-\alpha}$，这是与加速比直接挂钩的量；
- **Per-position acceptance rate**：逐位置接受率，观察随位置衰减的速度——衰减快说明 $\gamma$ 设长了，白打草稿。

Prometheus 侧有对应的累计计数器（`spec_decode` 前缀的 accepted/draft token counter，指标名随版本演进），可用于长期看板。调参闭环：**用真实流量压测 → 看 mean acceptance length 与端到端 TPOT → 扫 `num_speculative_tokens` 取最优 → 分流量类型决定开关**。代码类流量与闲聊类流量的接受率差异显著（第 8.1 节），值得分池配置。

---

## 📝 总结

- **有效性根源**：小 Batch Decode 是 Memory Bound，算力空转；一次前向验证 $\gamma$ 个 Token 的墙钟时间 ≈ 生成 1 个 Token，验证近乎免费。
- **加速比公式**：$S = \frac{1-\alpha^{\gamma+1}}{(1-\alpha)(\gamma c + 1)}$——接受率 $\alpha$ 是命门，草稿开销 $c$ 必须小，$\gamma$ 存在最优值。
- **无偏性**：接受概率 $\min(1, p/q)$ + 残差分布 $\mathrm{norm}(\max(0, p-q))$ 重采样，逐案分析可证输出严格服从 $p$；单 Token 接受率恰为 $1 - D_{TV}(p,q)$，指明提升方向是**让 $q$ 逼近 $p$**。
- **草稿谱系**：独立小模型（要过词表、分布、部署三道坎）→ N-gram/Suffix（零成本，吃输入输出重叠）→ Medusa（多头 + 树注意力，但并行头无因果链且默认验证非严格无损）→ EAGLE-1/2/3（特征级自回归 → 置信度动态树 → 多层特征融合 + training-time test）→ 预训练内置草稿的 MTP/DSpark（见 5.6）。
- **收益边界**：任务越可预测收益越大（代码/摘要 > 闲聊）；Batch 大了算力不再空闲，收益衰减甚至为负——投机解码是**拿富余算力换延迟**的延迟优化；与量化收益不可相乘，MoE 下验证不再免费。
- **vLLM 落地**：`--speculative-config` 统一配 ngram / eagle / draft model 三类方案，核心参数 `num_speculative_tokens`；用 draft acceptance rate 与 mean acceptance length 两个指标闭环调参。

## 🎯 高频面试题解析

**Q1：投机解码的原理是什么？大模型与小模型如何选择搭配？草稿模型是否需要微调？**（理想汽车 AI Infra 一面）
三段式作答。原理：Decode 是 Memory Bound，Draft 便宜地猜 $\gamma$ 个 Token，Target 一次前向并行验证，Rejection Sampling 保证输出与 Target 同分布，无损（第 1、2、3 节）。搭配：同家族同词表是硬约束，Instruct 配 Instruct 对齐分布，大小取 Target 的 1/10~1/50 量级在 $\alpha$ 与 $c$ 间折衷（第 4 节）。微调：非必需（无偏性不依赖 $q$ 质量），但在目标流量上蒸馏对齐能显著提升接受率——接受率的理论上界是 $1 - D_{TV}(p,q)$，微调就是在缩小这个距离（第 3.5、4.2 节）。

**Q2：投机采样中草稿模型与主模型的交互流程是怎样的？vLLM 与 SGLang 的实现有何差异？**（小厂 AI Infra 实习一面）
交互流程按第 2.2 节伪代码走：Draft 自回归猜 $\gamma$ 个并保留各步分布 → Target 一次前向得 $\gamma+1$ 个分布 → 从左到右接受/拒绝/残差重采样 → 全收则加 bonus Token → 拒绝位置之后的草稿作废并回滚 KV。实现差异的要点：vLLM 以 `--speculative-config` 统一收口，方法覆盖面广（ngram、独立 draft model、EAGLE/EAGLE-3、Medusa、DeepSeek MTP），投机流程嵌在 V1 引擎的调度循环内，Rejection Sampler 是 GPU 算子；SGLang 则以 EAGLE 系树草稿为主打路线，用 `--speculative-algorithm EAGLE(3)` 配合 `--speculative-num-steps`、`--speculative-eagle-topk`、`--speculative-num-draft-tokens` 显式控制树的深度、宽度与预算（第 2、7、9 节）。

**Q3：Decode 阶段属于 compute bound 还是 memory bound？**（遂原科技 AI Infra 实习一面）
小 Batch 下是 memory bound：每 Token 计算约 $2P$ FLOPs，却要搬全部权重 + KV Cache，算术强度约 1 FLOP/Byte，远低于现代 GPU 数百的拐点；7B/FP16 模型每步光搬权重就约 7 ms，计算只要 0.05 ms。Batch 增大后算术强度线性上升，逐渐逼近 compute bound——这一转变同时是投机解码收益衰减的原因（第 1.1、8.2 节）。

**Q4：为什么投机解码是无损的？请证明接受的 Token 服从 Target 分布。**（Q1 的标准深挖追问，理想汽车一面高频延伸）
完整推导见第 3 节，答题主线三步：(1) 接受路径概率 $q(x)\min(1, p(x)/q(x)) = \min(p(x), q(x))$；(2) 总拒绝概率 $= \sum_y \max(0, p(y)-q(y)) = D_{TV}(p,q)$，恰为残差分布的归一化常数；(3) 两路径相加 $\min(p,q) + \max(0, p-q) = p$，分 $p \ge q$ 与 $p < q$ 两种情况验证即得。加分项：指出接受率 $= 1 - D_{TV}(p,q)$、结论对任意 $q$（含 one-hot 的 N-gram）成立、与温度/Top-p 兼容的条件是先对 $p$ 做同样的后处理（第 3.5 节）。

**Q5：介绍 MTP（Multi-Token Prediction）机制的原理与作用。**（小米 AI Infra 校招）
在本篇框架下先定位：MTP 属于"让模型在预训练阶段自带草稿能力"的自投机路线——训练时增加预测 $t+2$ 及以后 Token 的辅助目标提升数据效率与表示质量，推理时该模块可复用为与主模型天然对齐的草稿头，验证仍走本节的 Rejection Sampling 框架、依然无损。其结构细节（顺序模块保持因果链，与 Medusa 并行头的本质区别）、DeepSeek V3 的配置与接受率、以及后续 DSpark 的演进，详见 5.6 节专篇。

**Q6：Temperature 的数学原理是什么？Temperature、Top-k、Top-p 的作用顺序是怎样的？**（华为 AI Infra 实习二面；与投机解码的结合是常见追问）
Temperature 对 logits 做 $z_i / T$ 后再 softmax：$T<1$ 锐化分布、$T>1$ 平坦化；常规流水线是先温度缩放、再 Top-k 截断、再 Top-p 截断、最后归一化采样。与投机解码的结合点：验证时必须把同样的后处理先作用到 Target 分布 $p$ 上再做 Rejection Sampling，无偏性才相对"后处理后的 $p$"成立；且温度越高 $p$ 越平坦、与 $q$ 重叠越小，接受率与加速比越低——贪心解码常是加速比上限（第 3.5、8.1 节）。

**Q7：dLLM（扩散语言模型）与自回归模型有何本质区别？**（AI-Infra 综合面经题库；可与投机解码对比作答）
两者是打破"逐 Token 串行"的两条不同路线。dLLM 改变建模方式：以迭代去噪并行生成整段 Token，不再维护严格的从左到右条件分解，换来并行度但改变了输出分布的构造方式；投机解码不改变建模，自回归分布原封不动，只是用"猜 + 并行验证"重排计算顺序，数学上严格无损。一句话总结：dLLM 改的是"模型是什么"，投机解码改的是"怎么把同一个模型算得更快"（第 1、3 节）。

**Q8：投机解码在大 Batch / 高并发下为什么收益会衰减甚至为负？**（由 Q1/Q3 自然延伸的系统设计追问，也是 5.6 节 DSpark 的出发点）
两层原因：其一，Batch 为 $B$ 时开投机使每步前向 Token 数变为 $B(\gamma+1)$，算术强度提前触到算力拐点，"验证免费"的前提瓦解，验证时间随 $\gamma$ 线性增长；其二，机会成本——被拒绝的草稿 Token 消耗的算力本可服务其他请求，压低系统总吞吐。所以投机解码定位是拿富余算力换单请求延迟的延迟优化，高并发场景应关闭或按负载动态调节草稿/验证长度（第 8.2 节；动态调度的生产级方案见 5.6 节）。
